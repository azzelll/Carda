## Measurement state/event/effect sketch

`preparing` → `measuring` → `processing` → `complete`, with `too_dark`, `motion_detected`, `poor_contact` and other observable low-quality reasons leading to `retry`; permission denied, unsupported device, timeout, error and cancel are terminal or recoverable as specified by the event. Events: grant/deny permission, start, frame-window update, pause/retry, cancel request/confirm, app background/foreground, timeout, result acknowledged. Effects: request permission, bind/unbind CameraX and torch, acquire bounded samples, run SQI/metrics off main thread, persist **only accepted summary**, navigate/show message. Every terminal/background effect unbinds camera and disables torch. UI state holds availability reasons, never stale values; one-shot effects are only prompts/navigation. Updated Figma maps to these states/events rather than changing sensor logic.
