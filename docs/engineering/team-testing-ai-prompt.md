# Prompt untuk AI teman penguji Carda

Salin prompt berikut setelah membuka repository Carda pada branch `main` terbaru:

> Kamu membantu saya menguji Carda di **ponsel Android fisik**. Ini prototipe wellness, bukan alat medis. Mulai dengan membaca `AGENTS.md`, `docs/engineering/team-testing-handoff.md`, `docs/engineering/priority-validation-handoff.md`, `docs/engineering/support-feature-test-handoff.md`, `docs/engineering/requirements-matrix.md`, `docs/engineering/evidence-index.md`, dan `docs/ppg-quality-and-safety.md`. Ambil status dari checkout saat ini; jangan menganggap angka atau APK historis di dokumen sebagai hasil perangkat kami.
>
> Bantu saya cek JDK 17, Android SDK 36, `adb devices`, backend akun uji bila diperlukan, lalu **build APK sendiri dari commit `main` yang dicatat SHA-nya**. Catat SHA-256 APK yang benar-benar dipasang. Jalankan pengujian secara bertahap: F02–F04 (kamera/torch, SQI, semua jalur gagal), F05/F09 (hasil HR/PRV dan pembanding bila tersedia), F11/F12 (hanya kandidat riset debug), lalu F01/F06/F07/F08/F15/F16/F17/F18 dengan akun sintetis. F19 diuji di browser; F20 hanya setelah prasyarat signing/HTTPS/Play terpenuhi. F10/F13/F14 saat ini hanya diuji status tidak tersedia dan wording aman, bukan angka/diagnosis.
>
> Untuk setiap percobaan, tulis tabel: ID F/kriteria, commit, hash APK, ID/model HP dan API Android, kondisi, langkah, harapan, hasil aktual, lulus/gagal/terhambat, alasan penolakan/SQI bila ada, serta bukti anonim. Pisahkan tes software, emulator, HP fisik, pembanding fisiologis, dan usability. Hitung semua percobaan yang diterima **dan** ditolak. Jangan menyebut akurasi medis dari angka yang sekadar tampil. Jika pembanding tersedia, sepakati protokol, sinkronisasi waktu dan ambang penerimaan sebelum evaluasi akhir.
>
> Hentikan dan laporkan segera jika angka muncul setelah SQI gagal, torch tetap menyala setelah keluar, terjadi crash, atau ada kebocoran data lintas akun/jaringan/log. Jangan unggah frame, raw PPG/ECG, identitas peserta, token, email asli, file test-mail, APK, atau data mentah ke Git/chat publik. Bila langkah terhambat perangkat, alat, backend atau izin, tulis hambatan spesifik; jangan menandainya lulus. Berikan laporan bug yang bisa direproduksi ke tim engineering dengan commit/hash dan langkah tepat. Jangan mengubah kode atau men-tune ambang fisiologis selama sesi pengujian tanpa instruksi pemilik proyek.

Mulai dengan menanyakan model dan versi Android ponsel yang tersedia, apakah dapat dipasangkan lewat USB, serta apakah ada alat pembanding. Lanjutkan semua pemeriksaan yang tidak bergantung pada jawaban itu sambil menunggu.
