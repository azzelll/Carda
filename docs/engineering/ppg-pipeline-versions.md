# PPG pipeline and SQI versions

These values are **engineering heuristics**, not physiological performance claims. Source: `core/ppg/PpgPipeline.kt` and `RgbaRoiExtractor.kt`. Do not tune them against a final evaluation set. A physical camera/device study must measure false accepts, false rejects, metric error and accepted-result yield before thresholds can be called validated.

`QualityReport.score` is computed from observed issue count and is never an accuracy percentage. Camera RGB, torch/exposure behavior and skin/lighting conditions can alter all these observables. Store the pipeline version with each accepted summary and keep failed sessions out of history/trends/export. For PRV, require ≥30 seconds, ≥20 pulse intervals, cadence jitter ≤0.10, beat intervals 333–1500 ms and adjacent interval changes ≤0.25; these too are provisional and need synchronized PPG–ECG comparison. `ppg-0.3` is not a declaration that phone-camera HR or PRV is valid. The edge gate does not solve motion-correlated peaks, intermittent contact, or hardware variability; rejected and accepted rates must be measured on physical devices.

Extraction uses validated `ExtractionThresholds` from the recorded `QualityThresholds` configuration: minimum covered red60/255, red dominance1.15× each other channel, any-channel saturation250/255, red clip≤2 or≥253. The 4×4 grid is a computation layout, not a calibrated physiological threshold. Any changed parameter needs a distinct recorded pipeline version and fresh affected evidence.

## F11 optical research feature, separate from reported metrics

`spo2-feature-research-0.1` was an **internal unitless** red/green AC/DC ratio-of-ratios extractor, not a SpO₂ estimator. It recomputed the same configured `ppg-0.3` SQI on one bounded sample snapshot and required an available pulse frequency, ≥30 seconds, stable frame cadence, usable pulsatile red **and** green channels, and consistent ratio across two halves. The AC projection was measured at the accepted pulse frequency; the defaults (green DC≥15, relative AC≥0.005, half-ratio difference≤0.25) are synthetic-test gates, not physiological limits. Six focused fixtures passed at E-059. There is no calibration coefficient, validated saturation range, app `MetricResult`, history point or percentage output.

`spo2-feature-research-0.2` adds **green-channel per-pixel clipping** to the transient ROI aggregate. Red-channel clipping remains the HR/SQI input; green clipping independently blocks the unitless optical feature if any frame has more than 5% clipped green pixels. A synthetic 25%-green-clipped window still passed red SQI and was incorrectly accepted by the old feature extractor before this gate; the expected-red/green tests and current Android gate are E-20260930-002/004. The 5% limit is provisional and may reject many real phones; physical yield and reference error must determine whether it is useful. A [red/green PPG imaging study](https://pubmed.ncbi.nlm.nih.gov/31893325/) examines camera calibration challenges, but does not validate this Carda threshold or provide its coefficients.

Research on smartphone camera PPG reports sensitivity to camera processing and a need for [per-device calibration](https://www.frontiersin.org/journals/digital-health/articles/10.3389/fdgth.2023.1301019/full). The research feature must be paired with actual phone/reference readings and a separately frozen calibration/evaluation split before any absolute SpO₂ estimate can be considered. Green-channel clipping within a frame, exposure drift and population/range effects are not fully characterized by current ROI aggregates; those are open method and device-study gates.

## F12 respiratory research candidate

`rr-research-0.2` retains the separately gated 58–70-second baseline-modulation method and adds a **separate pulse-amplitude modulation branch**. The second branch runs only when the baseline component is too weak, derives a beat-amplitude envelope from an SQI-passing capture with an available pulse rate, and checks respiratory-band strength, competing frequencies and agreement between halves. Both methods use the same bounded capture snapshot and provisional cadence/artifact gates. The result records `rr-research-0.2-baseline` or `rr-research-0.2-amplitude` so later comparisons can separate their error and yield. A stable synthetic amplitude-only fixture produces a research candidate; absent modulation and a deliberately changing respiratory rate remain unavailable. The fixed-period beat bins and numerical gates are research heuristics. Neither method has phone-camera breathing-reference validation or production breaths/min output.

In a **debuggable** Android build, an accepted capture may show this unitless optical ratio and the independently gated F12 respiratory candidate in a prominent research note. `MeasurementEngine` passes that transient note only when constructed with `researchMode=true`; `MainActivity` sets it from Android's debuggable application flag. The ordinary `MeasurementSummary` keeps SpO₂/RR unavailable, and PDF/history receive only that summary. Source, pure-Kotlin and synthetic emulator UI checks are E-060; an accepted phone-camera capture and a release-install inspection remain open.
