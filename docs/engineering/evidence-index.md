Repository requirement/architecture documents are *sources*, not validation evidence.

## Entry schema

For each actual item, append one row with a stable ID `E-YYYYMMDD-NNN`, feature/criterion IDs, category (`synthetic`, `emulator`, `physical-device`, `reference-comparison`, `usability`, `expert-review`, `security-privacy`, `build-release`), test/protocol, observation date, code SHA/build/version, pipeline/model/threshold version, device/reference details, people/attempt counts where applicable, **outcome including failures/rejections**, aggregate-safe artifact path, owner and validity (`current`, `requires-rerun`, `superseded`, `invalid`). Link criterion evidence IDs back in the matrix. Avoid raw health data, images/frames, raw PPG, names, email, access tokens or identifying video in this repository.

## Invalidation and handling

An evidence entry supports only the exact versions and conditions listed. A change to camera configuration, extraction, SQI, filter, metric threshold, model, inference runtime, reference alignment or user wording must trigger an impact review; mark affected entries `requires-rerun` until a new run exists.
